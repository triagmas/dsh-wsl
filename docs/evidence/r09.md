# Issue #9 evidence — footer bar, versions, settings popover

Source-only and headless evidence for the 32 px footer bar. **No real WSL
execution and no launch over the owner's desktop were performed for this change.**

## Base and scope

- Base: `main` @ `f16ee139ed670f7906c3641c0ff8694760e094ee` (release `v0.1.0-beta.1`).
- Branch: `feat/r09-footer-bar`.
- New surfaces: `src/chrome/` (bar page), `src/popover/` (settings popover),
  `src/preload/chrome.ts`, `src/preload/popover.ts`.
- New pure modules: `src/main/core/footer.ts`, `src/main/core/versions.ts`,
  `src/main/core/workspace.ts`, `src/main/backend/github-versions.ts`.
- The upstream WebUI is unchanged: it moved from the window's own `webContents`
  into a `WebContentsView` placed above the bar, keeping the same partition and
  the same navigation/popup/permission hardening.

### Composition smoke

`composition:smoke` is not a page render: it bundles the real `Windows` class
(`scripts/build-composition.mjs`, `dist/test/composition.cjs`, excluded from the
packaged app) and drives it as the app does — `ensureMain()`, `showMain()`,
`publishStatus()`, `publishVersions()`, `loadBackend()` — on a real
`BrowserWindow` + `WebContentsView` pair under Xvfb, against a local HTTP server
on `127.0.0.1:<ephemeral>` standing in for `dsh web`.

It asserts 28 facts, including:

- the window hosts exactly one child view, its own `webContents` is the local
  `file://…/chrome/index.html`, and the view uses `persist:wsl-web-shell`;
- the bar is 30–34 px, ends at the window bottom and shows
  `WSL Ubuntu :<port>`, `Connected` and `DSH 0.2.1-rc.5` from the published
  snapshot;
- the view sits at `x=0`, `y=0`, full width, height exactly `content − 32`, never
  overlapping the bar;
- growing (940×620) and shrinking (760×520) the window re-lays out the view, and
  the bar follows;
- the first load stores the `wss_session` cookie in the app partition, a forced
  reload sends it back, the server does not answer 401, the page reports the same
  session value, and the cookie is still in the partition afterwards;
- an already open settings popover picks up a later `publishStatus(RECOVERING)`
  (the regression fixed in this change — verified by temporarily reverting the
  fan-out list and watching this check fail).
